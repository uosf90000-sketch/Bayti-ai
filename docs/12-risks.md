# 12. Risks & Mitigation — المخاطر وخطط المعالجة

> مرتبة بالأثر × الاحتمال. كل خطر له مالك وإشارة إنذار مبكر (Early Signal).

## 🔴 مخاطر وجودية (تقتل الشركة إن تُركت)

### R1 — دقة تحليل المخططات غير كافية
- **الوصف:** إن فهم النظام المخطط خطأ (غرفة مفقودة، مقياس خاطئ)، كل ما بعده هراء مكلف — وثقة المستخدم تُفقد من أول دقيقة.
- **الاحتمال:** عالٍ (المخططات السعودية متفاوتة الجودة: صور جوال، PDF ممسوح، خطوط يد).
- **المعالجة:**
  1. مسار هجين (CAD حتمي + CV + VLM) لا رهان على تقنية واحدة.
  2. **Human-in-the-loop إلزامي في الـ UX** — شاشة "أكّد مخططك" ليست فشلًا بل ميزة (والمستخدم يتقبلها لأنها 30 ثانية).
  3. Golden Set + بوابة قرار صريحة في الـ Roadmap (لا نتقدم لما بعد المرحلة 1 بدقة < 85%).
  4. تصحيحات المستخدمين = بيانات fine-tune تراكمية.
- **إشارة مبكرة:** نسبة المستخدمين الذين يصححون > 3 عناصر لكل مخطط.

### R2 — التسعير غير موثوق (روابط ميتة/أسعار قديمة)
- **الوصف:** مستخدم يضغط "اشترِ" فيجد سعرًا مختلفًا أو منتجًا منتهيًا — أسرع طريقة لتدمير المصداقية.
- **المعالجة:** تحديث أسعار ≤ 72 ساعة (يومي للمرحلة B)؛ عرض `as_of` بشفافية؛ فحص روابط دوري؛ نطاقات ثقة في الإجماليات ("±8%")؛ أولوية للمتاجر ذات feeds رسمية.
- **إشارة مبكرة:** نسبة الروابط الميتة > 5% أسبوعيًا.

### R3 — قانونية جمع بيانات المتاجر (Scraping)
- **الوصف:** متجر كبير يرسل إنذارًا قانونيًا أو يحجبنا → فقدان جزء من الكتالوج فجأة.
- **المعالجة:** أولوية مطلقة للاتفاقيات الرسمية (affiliate/API) — تبدأ من الأسبوع 1؛ الـ scraping المهذب مؤقت وانتقالي؛ **الحقيقة الاستراتيجية: نحن قناة مبيعات للمتاجر لا خصم — نأتيهم بمشترٍ جاهز القرار**، وهذا يجعل الاتفاقيات قابلة للإغلاق؛ تنويع (لا متجر > 30% من الكتالوج).
- **إشارة مبكرة:** حجب IP أو تغييرات مضادة للـ scraping متكررة.

## 🟠 مخاطر عالية

### R4 — تكلفة AI لكل مشروع تلتهم الهامش
- **الوصف:** مجلس من 11 وكيلًا + صور لكل غرفة قد يكلف دولارات كثيرة/مشروع، والمستخدم يدفع اشتراكًا محدودًا.
- **المعالجة:** تتبع COGS لكل مشروع من اليوم الأول (`ai_usage`)؛ model routing (رخيص للبسيط)؛ prompt caching؛ قوالب غرف معادة الاستخدام؛ حصص لكل باقة؛ التسعير يُبنى على COGS مقاس لا مُخمَّن.
- **إشارة مبكرة:** COGS/مشروع > 30% من سعر الباقة.

### R5 — صور فوتوريالية لا تطابق الغرفة الحقيقية
- **الوصف:** صورة جميلة لغرفة "خيالية" مختلفة عن غرفة المستخدم = خيانة للوعد الأساسي.
- **المعالجة:** conditioning هندسي إلزامي (ControlNet على depth/segmentation مولّد من الـ Graph)؛ eval بصري بشري أسبوعي؛ وإن لم تنضج التقنية: نطلق بـ "moodboard + مخطط موزع" الدقيقين بدل صور زائفة — **الدقة قبل الإبهار.**

### R6 — منافس عالمي (أو نموذج عام قوي) يدخل السوق
- **المعالجة:** خندقنا ليس النموذج بل: الكتالوج المحلي المنظف، بيانات المخططات الخليجية، اتفاقيات المتاجر، وفهم السياق المحلي (مجلس/ملحق/خادمة). السرعة في بناء هذه الأصول الأربعة هي الدفاع؛ نماذج أقوى تصبح **رافعة لنا** (نستبدل عبر الطبقة الموحدة) لا تهديدًا.

### R7 — الاعتماد على مزود LLM واحد
- **المعالجة:** طبقة LLM موحدة + اختبار failover دوري + prompts قابلة للنقل (بلا حيل خاصة بمزود) + evals تكشف انحدار الجودة عند التبديل فورًا.

## 🟡 مخاطر متوسطة

### R8 — فجوة توقعات: "AI يصمم كل شيء" مقابل الواقع
- **المعالجة:** تسمية صريحة للتقديرات (تشطيبات = نطاق سعري لا وعد)؛ إخلاء مسؤولية هندسي واضح (لا نتحمل الإنشائي)؛ UX يعرض الثقة لكل عنصر.

### R9 — بطء اتفاقيات الدفع/SMS/التوظيف محليًا
- **المعالجة:** مزودان بديلان لكل خدمة حرجة منذ البداية؛ التوظيف عن بُعد إقليميًا.

### R10 — تسرب بيانات مخططات المنازل
- **المعالجة:** وثيقة الأمان كاملة (تشفير، عزل مستأجر مُختبر آليًا، pentest قبل الإطلاق، خطة استجابة PDPL). الأثر السمعوي هنا أخطر من الغرامة — يُعامل كخطر وجودي في الأولوية التنفيذية.

### R11 — إدمان التوسع الأفقي المبكر (ميزات كثيرة، عمق قليل)
- **المعالجة:** قاعدة الـ Roadmap: لا ميزة خارج مسار "مخطط → قائمة مُسعَّرة" قبل Milestone B. مراجعة ربع سنوية للرؤية مقابل الواقع.

## إدارة المخاطر عمليًا

- مراجعة شهرية لهذه الوثيقة في اجتماع القيادة؛ كل خطر: مالك + إشارة مبكرة تُقاس فعليًا في لوحات المراقبة.
- أي خطر تتحقق إشارته المبكرة يرتقي لـ "قضية نشطة" بخطة أسبوعين.
